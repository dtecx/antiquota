# Rewrite integration tests

This directory owns reusable test support for the Rust rewrite. It does not change the captured Python baseline. The server integration entry point is `crates/server/tests/rewrite_contract.rs`; `tests/fake-agy` supplies the test executable. All subprocesses, account tokens, scripts, and project edits live in disposable directories beneath the current user's `Desktop/test`. Tests never start real agy or read real account credentials.

Build both binaries before running the integration test:

```sh
cargo build -p antiquota-cli -p fake-agy
cargo test -p antiquota-server --test rewrite_contract
cargo test -p antiquota-server --test accounts_contract
```

The harness sets `ANTIQUOTA_HOME`, `ANTIQUOTA_DIR`, `ANTIQUOTA_AGY`, `ANTIQUOTA_NO_USAGE_LINK=1`, and a fixture UI directory explicitly. The parent server retains the OS HOME only to resolve the allowed Desktop/test boundary; all application data uses the explicit isolated home and data roots. The seeded account uses synthetic token bytes with mode `0600` on Unix. Fake agy receives that account's isolated HOME and SSH environment; its invocation record excludes token bytes. Test child runtimes use two Tokio workers to avoid oversubscribing the computer during concurrent server tests. On Unix, local `open` and `xdg-open` interceptors record browser requests without opening a browser. Every test owns its server process and removes its disposable directory when finished. Evidence under `.handoff/evidence/` is ignored by Git.

## Captured contract coverage

`slice1-scope.json` lists all 75 captured routes individually. There are 22 distinct selected captured cases: an 18-case primary sequence, successful send/stop/delete cases in their controlled scenarios, and the `events-sse` case. That SSE case contributes eight selected first-turn samples. These assertions cover all ten Slice 1 endpoints. The 65 other endpoints remain individually pending; full chronological replay of all 172 cases is not claimed. The primary sequence covers health, state, authentication, Host validation, static containment, malformed and oversized bodies, session creation/get/update, invalid session inputs, empty sends, and shutdown. Separate whole-server tests cover queued sends, crash recovery, discovery, CLI execution, shutdown with an open SSE client, and exact restart replay. `coverage-proposal.json` maps precise passing tests and evidence to candidate feature IDs, with unproved acceptance behavior explicitly pending; it does not update the canonical report.

The first-turn SSE comparison uses original sample indices `7, 10, 12, 13, 14, 15, 16, 17` from `events-sse.json`. It checks every field in user, turn-start, both tool states, both deltas, assistant, and turn-end samples, including the file diff and usage. Each sample keeps its original JSON-pointer rules. Global account, approval, goal, job, thinking, and terminal events belong to later slices. The control scenario binds `SESSION_1` from its actual created session; the independent deletion scenario binds `SESSION_2` from another fresh created session. It verifies the captured deletion route response without claiming the original fork preparation, which is pending.

Comparison preserves exact object keys, array lengths, nulls, stable numbers, and strings. Only each fixture's explicit numeric JSON pointers are dynamic. Unknown comparison rules fail. Identities bind from the manifest's response pointers before later requests; paths stay exact after replacing the isolated test root. Recorded raw bodies are decoded from base64, preserving malformed JSON. Response `Content-Length` must match actual encoded bytes, and `Date` must be a valid HTTP date. The implementation's `Server` header may differ as recorded by the captured contract.

JSON numbers compare by exact decimal value: `0` and `0.0` are equal. The comparator removes insignificant zeros and combines decimal scale with the integer exponent; it never converts equality comparisons to `f64`. Distinct large integers such as `9007199254740993` and `9007199254740992`, different close decimals, and different exponent values fail. Exponents beyond the supported integer range remain equal only if their literal representations are identical. No numeric field is removed, and neither API nor data semantics change. Focused tests prove equality, inequality, signed zero, arbitrary-precision digits, and exponent handling. Dynamic timestamp/process rules retain their explicit numeric constraints.

SSE parsing decodes HTTP transport chunks first. It preserves JSON lines and UTF-8 bytes when an HTTP chunk splits them. Tests compare event content and durable replay, rather than transport chunk boundaries. Polls require both the expected turn count and its `turn_end` before treating a session as idle.

`state-initial` recreates its recorded two-account setup from the captured quota values, with a current timestamp at the fixture's explicitly dynamic timestamp pointer. The executable is copied to the isolated root, preserving the captured agy path. The test holds the first account's actual file lease before engine startup while checking `busy=true`, then releases it before session creation. No account or quota field is excluded.

## Account slice proof

The account target's latest full run passed 43 tests: 38 whole-application or CLI scenarios and five shared comparison/transport unit tests. Twenty additional immutable captured cases prove twelve routes: account list, probe, pause, check, delete, login start/poll/submit/cancel, routing, settings overview and defaults. Replaced login and validation errors retain exact keys, nulls and strings. These cases supplement the 22 selected Slice 1 captures; they do not claim full chronological replay of all 172 cases. All comparison rules remain those already recorded in the captures.

The settings case recreates its earlier own-stack state with the captured `antiquota` protection hook. The separate on-disk hook specimen is later chronological state with an additional example hook. The synthetic setup selects the protection entry explicitly; it does not edit either fixture or normalize away a response hook. Settings and quota tests retain unknown fields and arbitrary-precision integers.

Scenarios prove exhausted-quota and healthy-quota rate handoffs, auth parking, original conversation resume, a continuation nudge without a duplicate user prompt, no-id retries, conversation loss recovery, all rotation strategies, reserve ordering, warm account affinity, independent basket walls, verification repair, nonempty `today` including `turns`, model cache recovery and empty-probe retention. Exclusive locks are exercised by concurrent real engine processes and by a Python/Rust lock interoperability scenario. Cancellation during lease waits, quota probes and inherited output pipes prevents delayed descendant writes. Three-megabyte metadata output fails promptly without changing the cache.

Four full-application tests inject a fake `Clock` while using the real process and file adapters. They prove retry waits of 10 and 30 seconds, a 300-second cooldown and handoff, bounded repeated failure, cancellation during a retry wait, and ten seconds of preferred-account affinity. The test binary re-executes itself with isolated child environment; it never mutates process-global environment unsafely. Policy time advances without real sleeps. Short observation waits synchronize actual subprocess completion and cancellation.

Legacy CLI proof covers default/accounts, probe, stack/reseed, unwall, login, doctor, raw arbitrary argv and explicit slot forwarding, native TTY, quota/all-walled exit 75, and raw current success despite historical quota errors. Probe and raw quota paths leave an active engine's session metadata, event log, usage ledger and discovery bytes unchanged. Closing stdout fails promptly and kills descendants. The additive `chat` command remains a proposal in `CLI_PROPOSAL.md`; no compiled acceptance test invokes it. Existing HTTP tests prove durable session behavior, including an accepted prompt without accounts.

The local proof uses macOS and synthetic accounts. Windows/Linux execution, all five real account continuity checks, paid live scenarios, terminal UI, the desktop shell and every later slice remain separate acceptance work. `slice2-coverage-proposal.json` records precise candidate mappings and incomplete acceptance behavior for the canonical report owner.

## Fake agy scenarios

Set `FAKE_AGY_SCENARIO` to `success`, `delay`, `quota`, `rate`, `auth`, `approval`, `hook`, `background`, `goal_complete`, `huge`, `crash`, `stale_result`, or `duplicate_done`. The default success turn emits actual agy `event=init`, `event=step_update`, and `event=result` envelopes. Current-step usage is deliberately smaller than cumulative result usage. Resume ids stay stable. A successful synthetic file edit happens after the delay, immediately before the tool's completed frame is emitted. Cancelling during the delay prevents the edit.

`FAKE_AGY_SCRIPT` points to an isolated JSON file matching the Rust `Script` type. It can select scenarios by slot or turn, supply explicit event/delay actions, change usage or response text, and set exit codes. Normal tool progress waits 200 ms; `delay` waits 10 seconds unless `delay_ms` overrides it. `huge` defaults to 2 MB and is capped at 8 MB. The fake metadata commands, quota, sign-in, verifier, and dictation responses have no provider cost. Hook scenarios invoke only an explicitly supplied `antiquota` or `fake-hook` executable and never execute the proposed tool command themselves.

Scenario emission tests prove the fake protocol. They do not establish completed application support for goals, approvals, handoff, jobs, dictation, or other pending slices.

The account slice adds `transient`, `conversation_lost`, and `quota_no_init` scenarios. The last omits the initialization id and result conversation id so a failed first call can be retried with the original prompt. `scenarios_by_slot_and_turn` is a map from slot name to an ordered scenario list indexed by the session's invocation count; it takes precedence over `scenarios_by_slot`, `scenarios_by_turn`, and the default. These script options model provider behavior and do not enable application features.

The `metadata` object supplies `quota`, `quota_after_turn`, `quota_error`, `quota_delay_ms`, `verify_url`, `identity`, `models`, `skills`, `hooks`, and `config`. Quota values are whole actual agy command envelopes, so tests can represent disabled windows, malformed panels, and independent baskets exactly. `quota_after_turn` activates after a model call in that slot; zero-cost probes never increment the turn counter. `metadata_by_slot` chooses a complete per-slot metadata object with defaults, rather than recursively merging it with the global object. Models use `{id,label}` rows, and skill/hook responses use arrays of `{name}` objects as the real CLI does. Identity probes write only the synthetic email to the requested isolated log.

The `login` object controls `email`, `code`, `url`, `error`, `verify_url`, and optional `auto_complete_ms`. Its default URL matches the captured stub URL, and its default code is `good-code`. A rejected code creates no token or identity log. An accepted code creates a synthetic JSON credential file with mode `0600` on Unix and an empty account-state file. Automatic completion waits the selected milliseconds without reading a code. Sign-in remains in the fixture HOME; the fake does not open a browser or contact the URL. Application tests own adoption, replacement, cancellation, verification, and cleanup proof.

Metadata `inherited_pipe_ms` and `descendant_marker` create a guarded synthetic descendant that retains stdout/stderr and tries a delayed fixture write. Top-level `output_inherited_pipe_ms` and `output_descendant_marker` provide the same scenario for streamed raw output. These descendants run only the fake executable beneath Desktop/test; they never run a shell command or an arbitrary external executable.
