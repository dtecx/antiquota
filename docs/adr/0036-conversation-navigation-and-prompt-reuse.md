# ADR 0036: conversation navigation and prompt reuse

Slice 22 makes long agent conversations easier to use through three controls: Reuse on explicit user prompts, pane-local Find, and Jump to latest. These use the existing projected transcript, draft store, confirmation dialog and scroll-follow state. No engine routes, dependencies, provider settings or persisted formats change.

Reuse loads the exact earlier prompt text into its session's composer and requires an explicit Send. A different unsent draft needs confirmation. After confirmation, the action checks selection, loading, disposal and the original draft again, so an older action cannot overwrite newer work. Current composer attachments stay; earlier attachments are not added. Completion focuses the initiating composer only while its session remains selected. Generated goal, job and loop instructions do not get Reuse.

Find compares trimmed, case-insensitive literal text against visible prompt and reply source, including the current streamed reply. It returns one stable key per matching message. Thinking, tools and hidden goal instructions are excluded. The current message gets an outline; the count describes messages rather than individual occurrences. Existing escaped Markdown remains responsible for rendering, and queries are never inserted into markup or CSS selectors. Each split pane owns its query and navigation; changing sessions resets it. Cmd/Ctrl+F opens the active pane's finder, Enter and Shift+Enter wrap through results, and Escape closes it while preserving the result viewport and returning focus to Find. Composition events are ignored.

Jump to latest reuses the existing inclusive 120-pixel near-bottom threshold and per-session scroll positions. While the reader is farther away, new output preserves their position. Jump returns to the bottom, restores following and moves keyboard focus to the conversation region without an additional scroll. Search navigation and explicit scrolling use the same follow state.

Unit and browser proof cover draft replacement and cancellation, stale actions, exact text, attachment retention, inert queries, streamed keys, keyboard navigation, split-pane ownership, narrow layouts and new output before and after Jump. This small UI addition increases the compressed application bundle from 166.22 to 167.72 kB; Vite's default 500 kB uncompressed chunk advisory is now emitted. The advisory remains visible. Native webview and OS permission proof remain separate acceptance work.

The full browser gate exposed an existing account-state publication gap. A UI opened while a session waited for a lease could retain an idle account snapshot after the turn started, and a stopped turn could return before publishing release. The application now announces the actual account overview before the leased attempt and after the queue finishes and releases its session lock. Release publication failures are logged. Existing shared/exclusive leases and routing stay unchanged. An HTTP/SSE regression proves busy publication precedes TurnStart and that Stop publishes the released state; the quota browser test opens before Send and observes both changes without reloading. Older fuzzy Conversation locators now select the exact scroll region because Find adds another conversation-labelled control.
