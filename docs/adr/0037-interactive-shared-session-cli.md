# ADR 0037: Interactive terminal sessions

The owner requested a more useful harness and a Claude-style CLI on 2026-10-11. The existing bare command lists accounts, and `run` passes arbitrary agy arguments. Preserve both contracts and expose the shared-session harness as `antiquota -i`, with optional `--cwd`, `--model`, `--mode` or an exact `--resume` id. The proposed `chat` command remains unapproved and absent.

The CLI reuses the goal command's authenticated engine client and typed event follower. It opens SSE before sending, confirms completion from saved HTTP state and catches up without replaying completed replies. The follower also tracks pending approvals, current metadata and echoed prompts. Replayed approval frames cannot reopen a resolved request. All turns, routing, usage and permission decisions remain in the existing application services. Approval acknowledgements display the engine response, because another client may have answered first; missing or unknown decisions fail visibly.

Interactive startup discovers an engine or starts `serve --port 0 --no-open` as a background process. It uses a separate process group on Unix, and detached-process flags on Windows, so closing the terminal does not take down other clients. Unlike a bounded headless goal, interactive exit leaves the shared engine available. Ctrl+C/Escape stops only the current session; Ctrl+D during work stops it before exiting. Browser and terminal approvals share the same durable request, and terminal answers allow once or deny without writing permission rules.

Use pinned crossterm for cancellable keyboard events, bracketed paste, terminal size and raw-mode restoration, and unicode-width for prompt columns. The prompt uses terminal scrollback, a compact amber wordmark and headings, a single editable row with horizontal clipping and an explicit newline marker. Multiline paste remains an unsent draft. Up/Down history stays in memory and restores explicit user prompts when resuming, avoiding a second prompt-history file. Agent text, paths and paste cannot execute terminal control sequences. NO_COLOR disables heading color. The current editor moves by Unicode scalars; compound emoji grapheme editing is a documented limit.

The first background PTY test exposed a real hangup failure; the process-group correction has a passing exit-survival regression. Rust unit and real PTY/HTTP tests cover editing, replay, approvals, Stop, no-account durability and engine lifecycle. Chromium runs the binary inside the existing real xterm and proves the same conversation updates in the browser. No separate engine protocol, provider configuration, live account calls or new UI root is introduced.

Full-gate replay exposed concurrent status readers briefly taking the same account lease and reporting one another as busy. Overview reads now use the adapter's existing shared mutex; worker lease policy and captured API values are unchanged. A concurrent-reader regression fails before the correction, and the exact captured replay is repeated afterward.
