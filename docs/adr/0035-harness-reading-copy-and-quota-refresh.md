# ADR 0035: harness reading, copy and quota refresh

The existing transcript already copies individual prompts, completed replies and fenced code exactly. Slice 21 adds syntax highlighting and local wrapping to make code easier to read, a conversation clipboard action to reuse a complete exchange, and a single account-quota refresh action for practical multiaccount use.

Highlight.js 11.12.0 supplies its core and twelve explicitly bundled grammars: Bash, CSS, diff, Go, JavaScript, JSON, Python, Rust, SQL, TypeScript, XML/HTML and YAML, including their registered aliases. Fence hints are validated before rendering and never auto-detected. Unknown, unnamed or blocks longer than 20,000 characters use the existing escaped plain-text path. The limit bounds synchronous work; larger highlighting would need a worker. The library escapes source code in its generated spans; browser and unit tests keep hostile markup inert. See the [official highlighting API](https://highlightjs.readthedocs.io/en/latest/api.html). The UI dependency is pinned and adds no transitive dependencies. Its measured compressed application bundle grows from 142.63 to 166.22 kB.

A language, Wrap and Copy toolbar stays outside each code scroller. Wrapping changes presentation only, defaults off and exposes its state through aria-pressed. Clipboard text comes from the rendered code's textContent, preserving the source independently of syntax spans and wrapping. Existing theme tokens gain four syntax colors; the settled dark and light themes meet 4.5:1 for those colors and the toolbar text.

Copy conversation reuses the Markdown export formatter and existing clipboard adapter. It filters projected events to user prompts and completed assistant messages, preserving their source Markdown and order. The export format includes the session title, folder and model, and now gives each assistant reply an explicit antiquota heading. Thinking, tools, unfinished deltas and unsent drafts do not enter conversation copying; the full download continues to include its existing detail. No new clipboard or storage protocol is introduced.

Refresh quotas reuses the existing account store's mutation guard and exclusive per-account check endpoint. It snapshots slot names, checks each account's current busy/removed state before its request, and proceeds sequentially. Paused accounts retain their paused state. Newer SSE account snapshots win over stale check responses. Failures are collected without stopping later slots; the final status reports refreshed, skipped and failed counts, and a later refresh can retry. A quota check reports Refreshed instead of claiming the account is ready. A slot becoming busy after the UI check is still protected by the server's existing exclusive lease. No routing policy, account homes, credentials or provider configuration changes.
