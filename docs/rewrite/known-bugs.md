# Rewrite regression ledger

This ledger records the defects reported during the antiquota test run, verified historical fixes, separate implementation risks found while preparing the rewrite, and defects caught in the new Rust implementation. A fix in Python does not establish Rust parity. Every regression below needs a passing rewrite test before cutover. Evidence captured from real sessions is redacted and remains in the ignored `.handoff/evidence/` directory.

## Separate source findings and unconfirmed risks

These are not claimed as failures observed in the Gemini run. The rewrite must resolve confirmed policy gaps and explicitly test the other failure modes.

| ID | Finding | Evidence and confidence | Required treatment |
| --- | --- | --- | --- |
| R-001 | Agent-generated background commands bypass the tool approval policy. **Resolved in Slice 5.** | Confirmed source path: `_jobs_from_reply` calls `job_start`, which uses `subprocess.Popen(..., shell=True)` without `policy.decide` or an approval. The run used `sleep 600`; no destructive execution incident was observed. | Route agent-generated jobs through the same permission policy and approval stream as agent tool commands. User-started jobs retain their explicit authorization. |
| R-002 | A RUN_IN_BACKGROUND example or quoted instruction can be interpreted as executable output. **Resolved in Slice 5** for fenced code blocks and placeholders. | `_jobs_from_reply` searches the reply with `BG_LINE.findall`; no structured command boundary or code-block exclusion. No observed example-execution incident. | Define and test the accepted marker grammar, quoted/code-block cases and malformed commands before changing behavior. Record any contract change. |
| R-003 | Permanent approval may install rules for arbitrary-program runners. **Resolved in Slices 3 and 9a** for approval-always, permission PUT, normalized settings-file paths and stack permission imports. | `approval_answer(always=True)` calls `stack.allow_rule` with a suggested rule; no forbidden-runner validation appears in that path. No such permanent rule was approved in the stopped run. | Preserve one-time decisions, but enforce the hard rule against broad runner allow rules at all rule-writing entry points. |
| R-004 | Approval cards lose nested MCP arguments and truncate long strings. **Resolved in Slice 3.** | `approval_request` keeps only scalar values, truncating strings to 4,000 characters. This is a confirmed representation limit; no wrong decision incident was observed. | Typed approval events retain the data needed to judge a call; make truncation visible and test nested arguments/huge output. Document intentional API differences. |
| R-005 | Restored job watchers and scheduler threads start before all engine fields exist. | `Engine.__init__` starts job watchers and the scheduler before initializing keep-awake, approvals and terminals. Timing-dependent initialization failure is inferred, not reproduced. | Initialize services fully before spawning workers; test replay with already-finished and running jobs and immediately-due schedules. |
| R-006 | Restart preserves an active goal in metadata while clearing execution status; goals need explicit resumption. | Confirmed load behavior in `Engine.__init__`; the handoff restart helper explicitly resumes goals. No spontaneous goal-resume guarantee exists. | Specify restart recovery, approval cleanup and event replay; test it without replaying already-executed commands. |
| R-007 | Adopted job PID polling cannot recover the original exit code and may confuse PID reuse or a zombie process with a live job. | `_watch_job(proc=None)` uses `pid_alive`; inferred stale-job risk, no retained failure trace. | Test process identity, restart adoption, missing PIDs, exit status unknown, process-tree stop and duplicate wakeups. |
| R-008 | An isolated test engine bound a port but did not finish discovery/health startup. | Prior local test app showed its 30-second startup timeout; the isolated demo process listened on 8766 with no engine.json and health timed out. Cause remains unconfirmed; this is not evidence that the user's production engine had the same fault. | Capture a startup timeline and test partial-start cleanup, discovery atomicity, health readiness, bounded retry and shell respawn. |

## Stopped run observations

The retained fixer and auditor event logs contained goal/job-wait notices but no `error`, `wall` or `handoff` notices when inspected on 2026-10-07. `sleep 600` jobs and rounds waiting on jobs are expected behavior, not evidence of a stuck goal. Earlier turn-start records without matching ends can follow an engine restart; the available data does not establish their cause. The stop operation is verified separately in Phase 0 evidence.

The olx-mcp audit defects are defects in that project, not antiquota features or bugs. Its read-only state snapshot is `.handoff/evidence/phase0-olx-state.log`: local and VPS tracked source are at `ac71344`, version `0.2.1`; the local audit has seven open and zero fixed entries. Local `.gitignore` and `audit/` changes remain untouched. The active image contains the same version string, but lacks a Git revision label, and a runtime initialize request returned HTTP 401; exact image-to-commit attribution remains unavailable.
